### Task 1: The follow-ups and dependency fixes
- [ ] **1. Home shows a raw "Failed to fetch"** (`components/home.tsx` ~line 168). A network `TypeError` while starting a session shows the browser's raw text. Map non-`Response` failures in `SessionStarter.start` (or its home caller) to the existing `OPENING_PROMPT_FAILURE` copy ("Your message is still here…"), the same copy used for other opening failures. `components/new-session.tsx` ~line 338 shows the raw message the same way, so fix it too.
  - Test: a starter whose fetch rejects with `TypeError("Failed to fetch")` yields the `OPENING_PROMPT_FAILURE` copy.
- [ ] **2. Focus is lost when the dock flips to whole-content scrolling** (`components/dock-height.ts` ~line 77). With `interactiveWidget: "resizes-content"`, the Android keyboard shrinks the column, and the resize observer can flip the dock viewport to `overflow-y:auto`. A freshly created scroll container starts at scrollTop 0, which can hide the focused field.
  - After a flip to scrolling: if `document.activeElement` is inside the dock viewport, call `activeElement.scrollIntoView({ block: "nearest" })`.
  - Never move focus, and do nothing when focus is outside the dock.
  - Test the decision as a pure helper, for example `shouldRevealFocus(viewport, active, flippedToScroll)`: it is true only when the flip happened and active is inside the viewport.
- [ ] **3. The hints panel is clipped in a short window** (`components/canvas/hints.tsx` ~line 77). Change `max-h-72` to `max-h-[min(18rem,50dvh)]`.
- [ ] **4. The dictation-flow test depends on test order** (`tests/dictation-flow.test.tsx`). The first test needs a never-confirmed window-global store, and it breaks if tests are reordered. Give the store module a test reset, using the pattern the repo already uses for test seams (an exported `…ForTests` reset, or clearing the window global), and call it in a `beforeEach`. The test must pass when run alone with `--test-name-pattern` and in any order.
- [ ] **5. Admin status is cached as false after a transient `/api/me` failure** (the dictation PR's admin check; find where `/api/me` is fetched and cached for the dictation/language UI). Cache only successful responses, so that a failed fetch retries next time.
  - Test: one failed fetch followed by a successful one yields admin true.
- [ ] **6. The Users section stays busy after a network error** (`components/settings/users-section.tsx` ~lines 464-476). `setBusy(false)` is skipped when `refresh()` throws on a rejected fetch. Wrap it in `try/finally`.
- [ ] **7. Claude Code section loading state** (`components/settings/claude-code-section.tsx`).
  - After a failed GET, show the error and no "Checking…" status line.
  - Keep the toggle disabled until the first GET has finished, so a click can't PUT against an unknown state.
  - Render tests for both.
- [ ] **8. The Users editor offers Claude Code models** (`components/settings/users-section.tsx`). Its allow-list and per-user slot pickers must exclude `provider === "claude-code"` (reuse `isSlotPickable` from `model-menu.tsx`). The server already refuses them; this makes the UI agree.
  - Test: the per-user catalog has no claude-code entries.
